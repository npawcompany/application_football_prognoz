# Правила разработки

Для людей и для агента. Краткая копия для Cursor: `.cursor/rules/football-prognoz.mdc`.

## Язык и стиль

- Код, имена модулей, сообщения коммитов — английский.
- Строки интерфейса — русский.
- Python 3.11+, type hints на публичных функциях.
- Линтер/форматтер: `ruff`.
- Никаких секретов в git. `.env` в gitignore. В логах не печатать API-ключи.

## Архитектура

- Новый экран не вызывает `httpx` сам — только сервис.
- Новый внешний API — сначала запись в [DATA_SOURCES.md](DATA_SOURCES.md) (URL, лимит, поля), потом клиент.
- Не подменять локальную модель вызовом ChatGPT вида «кто победит».
- Кэш обязателен для любых сетевых данных.

## Данные и этика

- Соблюдать ToS football-data.org: не выкладывать полный дамп API, не долбить лимит.
- В UI явная подпись: прогноз статистический, не совет ставить деньги.
- Текст диплома: [VKR.md](VKR.md). Наивная схема «5 матчей + округление» — только база для сравнения, не движок 1X2: [HEURISTIC_FIVE_MATCH.md](HEURISTIC_FIVE_MATCH.md).
- Не хранить персональные данные пользователей.

## Git

- Коммиты атомарные: docs / data-client / model / ui раздельно, если возможно.
- Не коммитить `data/cache/`, CSV-дампы, `.db`, обученные тяжёлые артефакты.

## Тесты

- Клиент API тестируется на фикстурах из `data/samples/`.
- Живой API в CI не вызывается.
- Модель: сумма вероятностей ≈ 1, детерминизм на фиксированных фичах.
- Explainer: мок LLM, в промпт попадают факты матча.

## Зависимости

- Новая библиотека — только если закрывает пробел стека. Перед добавлением прочитать официальные доки ([DOC_STUDY.md](DOC_STUDY.md)) и зафиксировать версию в `pyproject.toml`.
- На старте не добавлять LangChain / LlamaIndex: один прямой вызов OpenAI или Ollama.
